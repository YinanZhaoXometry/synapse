# 02: GraphQL register/login mutations + current_user context + login rate limit

**What to build:** `register`/`login` mutations (thin: parse → authorize n/a → command → map Result) returning `{ token, user }`; GraphQL context resolving a memoized `current_user` from the Authorization bearer header — absent/invalid → `UNAUTHORIZED` for any op requiring auth; login attempts rate-limited per window (api-local storage, A2; value in config). `schema.graphql` grows by exactly these two mutations + User type.

**Blocked by:** 01.

**Status:** done

**Bound by:** AD-15 (bearer not cookies; rate-limited login), AD-12 (thin resolvers over commands; `extensions.code` presenter).

## Comments

Built 2026-11-04 on `epic/p2-2-t02-mutations` (base `epic/p2-2-auth` @ `40f183d`). Gates: rspec **218 examples, 0 failures** (182 baseline + 36 new), rubocop **127 files, no offenses** (115 baseline), schema dump re-dump idempotent (`schema_dump_spec`), web codegen regenerated `src/types/graphql.ts` (gitignored, not committed) and `frontend/node_modules/.bin/tsc -b` green — no frontend file changes landed.

**Schema diff shape (the contract movement):** `type Mutation { login, register }` + the Relay-classic plumbing the scaffold's `BaseMutation` convention generates (`LoginInput`/`LoginPayload`, `RegisterInput`/`RegisterPayload` with `clientMutationId`) + `type User { id: String!, email: String!, createdAt: DateTime! }` + `scalar DateTime`. No logout (pinned by `spec/graphql/auth_surface_spec.rb`, which also pins MutationType == exactly {register, login} and UserType == exactly {id, email, createdAt}). `id` is a plain uuid String — no GlobalID (AD-12); `password_digest` and every other credential material stay off the type.

**House `Types::DateTime` scalar (the one surprise):** the built-in `GraphQL::Types::ISO8601DateTime` prints into the IDL as `scalar ISO8601DateTime @specifiedBy(url: ...)`, and printing that String directive argument goes through `GraphQL::Language.serialize` → `JSON.generate(..., quirks_mode:)` → **ArgumentError on the json gem 3.x bundled with Ruby 3.4** — the same breakage class that made this scaffold dump IDL-only (introspection JSON); it only surfaced now because the scaffold's schema had no argument-carrying directives to print. The upstream fix (PR #5699, "Support JSON 3") first ships in graphql-ruby **2.6.8**, outside the pinned `~> 2.5.26` — a stack-pin bump is not this ticket's scope. So `createdAt` uses `Types::DateTime` (`app/graphql/types/date_time.rb`): a directive-less scalar that delegates `coerce_input`/`coerce_result` to the built-in ISO8601DateTime. Same wire format for clients; the dump stays printable on the pinned gems. If the graphql pin ever moves past 2.6.8, the built-in scalar could come back.

**Mutations (`app/graphql/mutations/register.rb` / `login.rb`):** thin per AD-12 — `resolve(email:, password:)` → `command_result(Accounts::<Register|Login>UserCommand.call(...))`. The shared `Mutations::BaseMutation#command_result` maps `Success` → the payload value and `Failure` → `GraphQL::ExecutionError` shaped by the epic-01 `ErrorPresenter` (`message` = English log line, `extensions.code` = closed enum): duplicate/shape/short-password → `VALIDATION_FAILED`, wrong credentials → `UNAUTHORIZED`, tripped window → `RATE_LIMITED`. `ApiSchema` gained `mutation(Types::MutationType)` (the scaffold had it deliberately unwired until the first mutation).

**Rate limiter — `Accounts::LoginRateLimiter` (`app/lib/accounts/login_rate_limiter.rb`, sibling of TokenCodec; not a command):** in-memory fixed-window attempt counter keyed by the downcased email (A2 — api-local, per-process; restarts clear it, accepted v1). API: `.attempt(email, now:, threshold:, window_seconds:)` — one call = one decision: records the attempt and returns true while the window holds < threshold attempts; false once tripped (a denied attempt is NOT recorded, so the lockout always ends exactly at the window boundary, never extends). Deterministic: `now:` injectable (default `Time.current` evaluated per call), window index = `now.to_i / window_seconds` — window reset is proven by moving the injected clock past the boundary, no sleeps. Config: `LOGIN_RATE_LIMIT_THRESHOLD` (default 10) + `LOGIN_RATE_LIMIT_WINDOW_SECONDS` (default 60), read from ENV at call time with sane fallbacks for garbage values (AD-12 posture, no settings gem). Puma thread-safety via a Mutex around the store; old windows pruned lazily. **Invocation point: command-level** — `Accounts::LoginUserCommand#call` checks the limiter BEFORE any credential verification (never touches bcrypt when tripped), so `RATE_LIMITED` wins even for a correct password (pinned both at command level and over HTTP). Justification: keeps mutations parse→command→map thin, and the command is the single choke point for credential verification — every transport gets the same protection; the failure rides the existing Result→ErrorPresenter pipeline with no new boundary plumbing. Register is deliberately NOT limited (login only, v1 — pinned by a spec). `.reset!` is a test-only hook; the whole suite resets the store between examples (`spec/support/login_rate_limiter_reset.rb`) so cross-example accumulation can never skew an example — tripping is always within-example work.

**Context resolver — `CurrentUserResolver` (`app/graphql/current_user_resolver.rb`):** GraphqlController builds one per request into `context[:current_user]` from `request.headers["Authorization"]`; it is **lazy + memoized** — nothing (header parse, `Accounts::TokenCodec.decode`, `User.find_by(id:)`) happens until the first `#user` call, and at most once per request. API for epic-03: `#user` → the User or nil (never raises); `#decode_error` → `:expired | :invalid | nil` (nil when the token verified but the user row is gone — stateless, no denylist). Bearer parsing accepts the scheme case-insensitively; a header without the scheme or absent counts as `:invalid`. Both decode reasons map to one `UNAUTHORIZED` at the guard; the distinction only reaches the log line (never the response — it would leak token state). Deliberate deviation from the ticket text: `User.find_by` instead of `User.find` — a valid token for a deleted user resolves to nil → `UNAUTHORIZED`, keeping the boundary never-raise instead of surfacing RecordNotFound as a 500.

**The guard — `Mutations::BaseMutation#current_user!`:** the seam epic-03's operations call to demand auth: returns the User or raises `GraphQL::ExecutionError("authentication required", extensions: { code: "UNAUTHORIZED" })`. Per-op enforcement starts with epic-03; register/login/health stay public (pinned by `spec/graphql/auth_guard_spec.rb`, which drives a spec-only probe mutation on a real schema subclass through the exact execution path epic-03 will use — absent/garbage/expired/no-resolver-at-all all yield UNAUTHORIZED — without touching the committed contract).

**DoD scoping re-proof:** `spec/requests/graphql_auth_spec.rb` logs in over HTTP, resolves the response token through `CurrentUserResolver` (the exact object the controller wires), and asserts the epic-01 scoping surface on the JWT-backed user (`study_plans` lists only the owner's rows, `find_by` on a foreign row → nil, `find` → RecordNotFound).

**For ticket 03 (demo seed):** the login-proof can either go through HTTP (`mutation { login(input: { email:, password: }) { token user { id email } } }`) or call `Accounts::LoginUserCommand.call(email:, password:)` directly (same Success shape `{ user:, token: }`) — note the command counts against the limiter, irrelevant for one seed login but worth knowing if the seed ever loops. User type fields available to the client: `id` (uuid string), `email`, `createdAt` (ISO-8601). Token claims: `sub` = user uuid, `exp` = mint + 24h, HS256 with `JWT_SECRET`.
