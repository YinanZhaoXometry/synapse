## Comments

- **2026-11-05 implementation — renderer decision (delta review decision 1, criteria trail):** custom SVG, deterministic stage-column layout, ZERO new dependencies. (a) bundle discipline (NFR-6) — reactflow/d3 cost 60–150KB gz for layout we don't need; (b) the data model is a total `order` + stage labels, so deterministic columns ARE the structure-faithful rendering — a force/dag layout would be less faithful; (c) AD-9's keyboard path is trivial on semantic SVG (`tabIndex` per node `<g>` + roving tabindex) vs fighting a library's focus model; (d) the lazy-import posture is moot (no lib to split). Layout in the pure module `frontend/src/features/plans/roadmap-layout.ts` (10 tests): stages ordered by their first node's `order`, nodes stacked within the stage column in `order` (ties broken by id — byte-identical output regardless of input order, pinned), edges = consecutive-`order` same-stage pairs on the global order walk + ONE connector per column boundary (last node → next column's first node, including into the default column), cubic bezier paths between facing ports. Stage-less nodes park in a TRAILING default column (i18n `plans.stageUngrouped` 未分组/Ungrouped — the tree's `stageUntitled` em-dash convention stays tree-only). Fixed box geometry (172×60, no DOM measurement); the 36-node fixture pins determinism and per-column no-overlap.
- **The UX-spine choice:** the spine names the graph "a view tab inside Plan Home" (EXPERIENCE.md Phase-2 positions — honored: a List/Roadmap pill toggle above the nodes zone, list stays default) but is SILENT on detail panel-vs-side-sheet. Chose the SIDE SHEET (shadcn Sheet, right) and recorded why: the canvas stays visible and pannable behind the sheet (a modal dialog would cover the thing being navigated), it matches DESIGN.md's floating-layer posture (shadows belong on sheets/popovers), and it reuses the scaffold sheet anatomy. The sheet carries the SAME `NodeStateBadge` + node title + score (`hasEvidence ? score% : "—"`, the row display rule) + the T3 click-through actions.
- **The T3 action set is now ONE implementation:** the row's study/jump-menu/Quick Test markup extracted into `node-actions.tsx` (`NodeActions`); NodeRow and the graph's detail sheet render it verbatim — targets resolved ONLY through `nodeJumpTargets`/`nodePrimaryAction` (the REAL anchor builders, AD-8, consumed verbatim). State vocabulary on the graph node face rides a new `NODE_STATE_FACE` addition to the shared `node-state.ts` contract (the same state tints as the pill classes, as SVG-consumable CSS-var styles — glyph + tint on the face, AD-9 not color-only, server fields only, AD-14).
- **Interaction (AD-9):** every node a `<g role="button" tabIndex aria-label>` (label = `plans.graphNodeAria`: title + state); roving tabindex — up/down within the column, left/right across columns at the same row index (clamped to the target column's size), Enter/Space opens the detail, Esc closes; the focused node renders the semantic-token focus ring (`--accent-ring`). Pan = pointer drag on the canvas wrapper (translate); zoom = +/−/reset buttons + ctrl/cmd+wheel (a NATIVE non-passive wheel listener — React's root wheel is passive and would swallow the preventDefault), clamped 0.5–2. Motion: the transform transition class is applied only when ThemeContext's motion pref is on (`data-motion="on|off"`, pinned); the global prefers-reduced-motion + body.reduce-motion rules kill it regardless.
