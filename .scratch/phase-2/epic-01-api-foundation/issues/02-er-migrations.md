## Comments

For epics 03 (factories + scoping context) / 04 (first GraphQL surface) and later epics — every field-level decision made here beyond the spine's names + ownership:

- **Migration order (FK dependencies):** users → study_plans → knowledge_nodes → materials → study_tasks → quiz_sessions → questions → evidence_records → flashcards → mistake_entries → chat_threads → reading_progresses → section_markings → annotations → ValidateTaskForeignKeys (timestamps `20261104090001`–`…090015`). The task↔node/material triangle is mutually referential, so `CreateStudyTasks` adds `add_foreign_key … validate: false` for `knowledge_nodes.task_id` / `materials.task_id` and a separate `ValidateTaskForeignKeys` migration validates them — strong_migrations rejects the validating form. `db/schema.rb` is committed (dumped fresh; `ActiveRecord::Schema[8.1]`, version `2026_11_04_090015`).
- **uuid posture (AD-12/A2):** every table `id: :uuid, default: "gen_random_uuid()"`; FK columns all `type: :uuid`. `create(id:)` is honored by plain AR (no custom code); per-model specs assert both the server default and a client-supplied id. Factories (03): do NOT pre-assign ids — let the server default fill them.
- **Scoping (AD-13):** every table except users carries `user_id uuid NOT NULL` FK, indexed (references' default index). Models: `belongs_to :user` required (Rails 5+ default) on all 13 — a nil user is invalid at the model seam; that plus the column is the whole scoping surface for now (command-layer enforcement + shared context are ticket 03's). User `has_many` names: `:study_plans, :materials, :knowledge_nodes, :study_tasks, :quiz_sessions, :questions, :evidence_records, :flashcards, :mistake_entries, :chat_threads, :reading_progresses, :section_markings, :annotations`.
- **Enum storage (implementer's call, recorded):** closed vocabularies are string columns pinned TWICE — PG check constraints (database floor) + Rails `enum` with `scopes: false` (model seam; scopes are off because several values collide with Ruby/Kernel names: `private`, `open`, `empty`). Enum assignment of an out-of-vocab value raises `ArgumentError` immediately (Rails default `validate: false`) — the command layer maps that to `VALIDATION_FAILED`. Values: visibility `private|public` (**assumption** for FR-38/Square — adjust if the Square epic wants a third state) · kind `pdf|markdown` · parse_state `pending|parsing|parsed|failed` (default `pending`) · parse_failure_reason `corrupt|encrypted|empty|unknown` (nullable) · mode `open|choice|mix` · status `active|completed|abandoned` (default `active`) · question kind `open|choice` · outcome `correct|partial|wrong` · difficulty `hard|medium|easy` (nullable — self-rating only, never evidence).
- **Defaults stamped by the DB:** visibility `private`; parse_state `pending`; quiz status `active`; materials.sections `'[]'`; chat_threads.messages `'[]'`; mistake_entries.forfeited `false`. NOT stamped: `section_markings.claimed_at` has no DB default (the command layer sets it at claim time); `knowledge_nodes.order` has no default (clients supply).
- **No join table for StudyPlan ↔ Material:** the `}o--o{` attaches edge is realized plan-side via `materials.plan_id` (nullable FK). One material row per attachment; `materials.plan_id` is deliberately NOT unique (a plan has many materials); TS `materialIds`/`nodeIds`/`questionIds` are has_many inverses, never columns.
- **Dual task↔node FKs kept (AD-6):** `study_tasks.node_id NOT NULL` FK **and** `knowledge_nodes.task_id` nullable FK — both directions of the TS shape. The `||--||` 1:1s are enforced by unique indexes: `knowledge_nodes.task_id` unique, `materials.task_id` unique (nullable unique = many NULLs fine). **Factory insert order (03):** create node (task_id null) → create task (material + node) → set node.task_id — the pair is circular; the same dance applies to material.task_id.
- **jsonb columns, TS keys verbatim (AD-2):** `materials.sections` (MaterialSection[]) · `questions.options` (string[]) · `questions.keywords` (string[]) · `mistake_entries.source_location` (ReadingLocator) · `chat_threads.messages` (ChatMessage[] — includes `createdAt`) · `reading_progresses.position` (ReadingPosition `{locator, text}`) · `annotations.locator` (ReadingLocator). **Keys inside the JSON stay camelCase exactly as the TS shapes (`sectionId`, `createdAt`, `kind`, `page`) — do NOT snake_case them**; AD-2 says the locator type is consumed verbatim. Adding MaterialSection/ChatMessage entities was rejected (would rename the spine); ReadingLocator JSON = `{kind:"pdf",page}` | `{kind:"markdown",sectionId}`.
- **FK constraints beyond the ER's edges (integrity on TS-shaped references):** `evidence_records.session_id` and `mistake_entries.session_id` → quiz_sessions (nullable); `questions.source_material_id` → materials; `questions.node_id` → knowledge_nodes. Safe because nothing hard-deletes in scope. Deliberately NOT FKs: `questions.source_section_id` and `section_markings.section_id` are **string section slugs** (`page-N` / markdown slugs — MaterialSection ids), not uuid references.
- **users shape (AD-15 structural only):** email NOT NULL + unique index + presence/uniqueness validation; password_digest NOT NULL (the bcrypt gem + `has_secure_password` land with the auth epic — only the column shape is set here). **Validation posture across all models is minimal by design:** `belongs_to` requiredness + the User email validations are the only model-level checks; NOT NULLs and check constraints are DB-enforced, and richer validation belongs to the command-layer epics (machines `create!`-raising `ActiveRecord::RecordInvalid` / `NotNullViolation` / `ArgumentError` into typed Failures).
- **Timestamps everywhere:** Rails `t.timestamps` on all 14 tables, including where the TS shape only declared createdAt (StudyTask got updated_at) or updatedAt (ReadingProgress, ChatThread got created_at) — harmless by convention; `updated_at` is what a future FR-24 re-queue scan compares.
- **Odd-but-honest columns:** `knowledge_nodes.order` — TS field name verbatim, a reserved SQL word that ActiveRecord always quotes (verified green); `questions.correct_option_index` integer nullable; `materials.size_bytes` bigint.
- **Models are flat** (`app/models/`, no namespaces); `belongs_to :plan/:task/:node/:session` carry `class_name:` where the ER name differs (`StudyPlan`, `StudyTask`, `KnowledgeNode`, `QuizSession`); nullable FKs all `optional: true`.
