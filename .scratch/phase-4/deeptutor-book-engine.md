# DeepTutor's Book Engine — the generated-content route, structured

Status: research artifact · 2026-11-11 · companion piece to the plan-content research (owner's「有了计划，没有学习内容，我怎么学习？」question). Source: local snapshot `../DeepTutor-main`, all paths under `deeptutor/book/` unless noted. This is the **C档** (generated static lessons/books) the A/B/C proposal recommends REJECTING for Synapse — written down so the rejection is informed, and so the three salvageable parts are on record if they're ever wanted.

---

## 1. One-line definition

Give it a subject (optionally grounded on your knowledge bases) and it writes a complete book — not a document summary, but a chaptered, paged, interactive textbook (figures/quizzes/flashcards inline), every page generated by the LLM.

Product copy: "Name a subject and DeepTutor writes you a book on it — a spine of chapters first, then each page written out in full." (`web/locales/en/app.json:4424`)

## 2. The generation pipeline — four stages, TWO user-confirm gates

`engine.py` lifecycle (both gates deliberate: **the user sets the direction; the AI produces the content**):

```
① create_book(user_intent, 知识库, 聊天选段, 笔记引用…)
   → BookProposal（书名/定位/读者对象）          ← user confirm #1 (editable)
② confirm_proposal(edited_proposal)
   → Spine（章节大纲：章 + 小节 + 目标）          ← user confirm #2 (editable)
③ confirm_spine(edited_spine)
   → pending page shells + queued compilation
④ compile_page(book, page)
   → per-page block-by-block generation (background worker)
```

- `create_book` signature takes `source_refs / chat_selections / notebook_refs / knowledge_bases` (`engine.py:467-475`) — generation is grounded on the user's KBs (`engine.py:179, 529-530`).
- Key posture: **spine first, prose second** ("Edit the chapter spine before a word is written"). Editing the spine pre-writing is free; after writing, only `rebuild_book` exists — discard EVERY page and regenerate from the spine (`engine.py:16-19`).
- `resume_book` re-queues unfinished pages **keeping what exists**; `rebuild_book` is the destructive one.

## 3. Page format — the typed-block compiler

A page is not a markdown string but a **sequence of blocks**, one generator per type (`blocks/` — one file per type), dispatched by a `BlockGeneratorRegistry` (`blocks/base.py`). `BlockType` enum (`models.py:59-76`):

| Phase | Types | What |
| --- | --- | --- |
| 1 | text · callout · quiz · user_note | prose, highlight boxes, **in-page quizzes**, user annotations |
| 2 | figure · interactive · animation · code · timeline · flash_cards | svg/chartjs/mermaid figures, interactive HTML, video animations, code, timelines, **in-page flashcards** |
| 3-4 | deep_dive · section · concept_graph | side-branch deep dives, long-form chapter sections, **concept graph rendered as the TOC overview** |
| Guided Learning | diagnostic · pretest · retrieval_practice | diagnostics, pretests, retrieval practice |

That's the "living book": interactive originals — quizzes/flashcards/concept-graphs grow INTO the prose, not as appendices.

## 4. Compilation runtime — async queue + circuit breaker

The engineering-heaviest part (`engine.py` module docstring + `_BookRuntime`):

- Per book: an `asyncio.Queue` of pending pages, ONE background worker, and an **in-flight table keyed by page id** — concurrent compile requests for the same page join a single run instead of racing duplicate generations.
- **Breaker**: `CONSECUTIVE_PAGE_FAILURE_LIMIT` provider-level failures in a row → the book enters `paused` (with `pause_reason`) rather than grinding remaining chapters into half-generated debris. (The Paused/Compiling statuses on the learning dashboard come from this — `LearningDashboard.tsx:100-115`.)
- Progress publishes to the book's **long-lived stream** (`event_hub.py`), never a request-scoped bus — background compilation keeps streaming after the call that queued it returns.

## 5. Relationship to the learning system (the decision-relevant part)

Books are **NOT** a per-KP lesson store. Two parallel lines, two hooks:

1. **Forward: a book is an attachable topic source for a mastery path.** `kind: "book"` is a valid source kind (`web/lib/learning-api.ts:420-429`); the wizard hydrates the spine's chapter titles/objectives as the excerpt (`useTopicSourceLibrary.ts:388-411`). During tutoring each WRITTEN chapter becomes a readable row (~24k chars, `MAX_CHAPTER_CHARS`); an unwritten chapter lists as `note="not written yet"` — "the tutor must be able to say 'this chapter exists but has not been written' instead of inventing its contents" (`topic_materials.py:101-148`).
2. **Backward: a book page's tutor chat can resolve to a mastery path** — page chats send `book_references: [{book_id, page_ids}]` (`BookChatPanel.tsx:418`); `resolve_mastery_path_binding` falls back explicit path → selected book → session-owned (`learning/identity.py:42-60`).

Reading experience shares the immersive-reading tracking (position/bookmarks/highlights — `progress.py:15`): "the tutor reads along with you."

## 6. Why REJECT for Synapse (the C档 verdict)

- **Product divergence**: Synapse's spine is「user brings their own materials + plans orchestrate the study」; books are「AI produces the content」— opposite directions. (Same verdict as uiux-comparison §6's book-engine rejection.)
- **Cost**: one book = dozens of LLM generations (multi-block per page) + a full runtime (queue/worker/breaker/event stream) + structured-block storage per page. Heavy infrastructure for a course project.
- **It doesn't solve the owner's actual question**: the need is「existing plans' nodes have something to study」— A档 (auto-run FR-45 mapping + per-node 讲解 companion entry) closes that loop generating NOTHING new.

## 7. The three salvageable parts (borrow without the pipeline)

1. **Spine-first two-gate confirmation** (outline settled & editable BEFORE any prose) — the correct order gate if B档 per-node teaching ever generates lesson content.
2. **Breaker + paused-with-reason + resumable** — the right posture for ANY batch AI generation feature (Synapse's quiz generation carries the same spirit; this is the complete version).
3. **concept_graph block** — the TOC rendered as a concept overview graph; mutual confirmation of Synapse's roadmap spine shape.
